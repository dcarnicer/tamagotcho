## What's new

- **Same-size deck updates are detected.** The update check now compares the
  installed pack's SHA-256 with the catalog when its size matches, not only the
  size. A rebuilt deck that keeps the exact same byte count finally shows up in
  **Decks > Updates**. The digest is read only when the size matches; a read
  failure falls back to the old size-only answer, never a false update.
- **Back up and restore progress from the portal.** **Advanced → Progress
  backup** downloads `tangocho-progress.bin` (every deck's kanji, the lifetime
  counters, the schedule) and can upload it back. The file is checked before
  anything changes; the progress it replaces stays on the device as
  `/state/srs.before-restore.bin`. Wi-Fi, language and time-zone settings and
  the deck files are not in the backup. Restoring is refused while a deck
  download runs.
- **Decks from your own kanji list.** `tamagotcho-pack build --kanji-file
  PATH` builds a pack from a UTF-8 text file with one kanji per line, for a
  textbook chapter or a class list. Comments and blank lines are allowed; the
  line order is the new-card order unless `--order jlpt|grade` overrides it.
  The deck name defaults to the file stem; `--name` still overrides it. No CSV
  or Anki import.
- **Install from the browser.** The new page at
  <https://dcarnicer.github.io/tamagotcho/> flashes a board from Chrome or Edge
  with ESP Web Tools. It is a **first-install** path: the merged image erases
  the settings (Wi-Fi, preferences, time zone) while decks and progress stay.
  Updates keep using the app-only image or M5Burner. The page is published by
  `.github/workflows/pages.yml` after every release.

**Updating from v0.4.2:** the app-only image keeps settings, decks and progress
(`write_flash 0x10000 tamagotcho-<board>.bin`). The `m5stack` image on M5Burner
is one entry for the StickS3 and the Cardputer ADV. After the update, **Decks >
Updates** may list decks installed from older builds: their size matches the
catalog but their SHA-256 does not. That is the new check working; updating one
keeps its progress.

**Checked on hardware** (2026-10-22):

- A local catalog declared the installed `n5-en` with its exact size (106,124
  B) but another SHA-256: the portal and the device's **Updates** list both
  showed it as an update. Holding it downloaded the published deck, removed it
  from the list and kept the deck at 5 due / 67 new.
- Progress backup: a 244-byte file with 12 records. After one wrong answer the
  counters went 15 answers / 2 Again → 16 / 3; restoring the backup returned
  them to 15 / 2, and the downloaded file matched the backup's SHA-256 byte for
  byte. A random 244-byte upload was rejected and changed nothing.
- A `--kanji-file` pack (日/月/火, 3 cards) was uploaded, loaded and deleted
  through the portal; the session stats stayed at 15 / 86 %.
- The normal `sticks3` build booted afterwards with 12 records, 5 due / 67 new
  and the saved deck and date. The official v0.5.0 `tamagotcho-sticks3.bin`
  then booted as `Tamagotcho v0.5.0` with the same state.
- **T-Display-S3:** the v0.5.0 app-only image booted with its JLPT N4 deck and
  its one progress record; the quiz, settings and setup portal rendered on the
  170×320 panel. Its update and backup flows were not exercised because it has
  no home Wi-Fi saved.
- **Cardputer ADV:** the v0.5.0 `m5stack` merged image booted, detected the
  board and the TCA8418 keyboard, and reached the first-boot language picker.
  The `cardputer-adv-shots` build rendered the language picker and the setup
  portal (access point `Tamagotcho-AAC8`, 5.9 MB free) on the 240×135 panel.
  Its original M5Launcher flash was backed up whole and restored afterwards,
  hash verified.

All four environments build (`sticks3`, `tdisplay-s3`, `cardputer-adv`,
`m5stack`); native tests: 234 passed, 1 skipped. The browser install page was
verified by serving its assets, not by a browser flash. The M5Burner version is
pending.
